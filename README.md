## coderivet

Software engineer working on long-lived codebases - the kind where architecture
spans generations of patterns, migration debt has to be paid down without
stopping delivery, and the bugs that matter most live at boundaries the linter
never sees.

Right now that means two worlds in parallel: a large Ember application where
Classic and Octane patterns coexist mid-migration, and a modern React codebase
built on feature-sliced architecture. Different stacks, same discipline - know
where your boundaries are, watch what crosses them, and make change safe while
delivery keeps moving.

---

### What I’m working on

Alongside day-to-day engineering, I’m developing RecurseWright - an evolving exploration of how humans, AI, methods, and tools can become a better engineering system through evidence, revision, and practice.

The first trace is now public: **[What Does It Mean to Be Embarrassed to Use a Calculator?](https://rw.krupnyak.com/articles/embarrassed-to-use-a-calculator/)**

The rest is being built.

---

### On AI in this work

I use AI as a structured collaborator: code review, context retention, pattern recognition, and exploring engineering decisions across codebases too large to hold in working memory at once.

But the more interesting question is no longer simply how AI can help with the work. It is what happens when the way we work with it begins to change too.

That question is part of what became RecurseWright.
